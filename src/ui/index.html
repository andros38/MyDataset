PANDUAN PENGGUNAAN
Mulai dari sumber sampai dataset siap dipakai
Panduan singkat ini mengikuti alur kerja MyDataset, bukan dokumentasi teknis.

        
      

      

        

          
          
          
          
          
          
          
        

        

          

            
1. Mulai proyek

            
    
              
  1. Pilih Metode Akuisisi. HAR / Network tetap menjadi metode yang direkomendasikan untuk dataset besar.
    2. 
              
  2. HAR / Network mendukung Traveloka, Tiket, Agoda, Trip, dan Booking.
    3. 
              
  3. Halaman Web / DOM tersedia kembali untuk Tiket, Agoda, dan Trip sebagai metode alternatif/interaktif.
    4. 
              
  4. Isi atau konfirmasi Nama objek / proyek sebelum proses dijalankan.
    5. 
            

            
Aturan dukunganHAR/Network = Traveloka, Tiket, Agoda, Trip, Booking. DOM = Tiket, Agoda, Trip. Traveloka dan Booking tidak dijalankan melalui DOM.

          

          

            
2. HAR / Network — Traveloka, Tiket, Agoda, Trip, Booking

            
    
              
  1. Buka halaman review di Chrome/Edge, tekan F12 → Network, aktifkan Preserve log bila perlu, dan bersihkan log sebelum pengambilan data.
    2. 
              
  2. Lakukan pagination seperlunya. HAR hanya dapat memproses response yang benar-benar terekam.
    3. 
              
  3. Klik kanan pada daftar Network lalu pilih Save all as HAR with content.
    4. 
              
  4. Kembali ke MyDataset dan pilih file HAR. Adapter akan dideteksi otomatis dari endpoint review.
    5. 
              
  5. Periksa coverage dan sumber yang terdeteksi, lalu tekan Proses file.
    6. 
            

            
Untuk review bahasa asing, MyDataset mengutamakan versi Bahasa Indonesia jika response menyediakan terjemahan Indonesia. Jika tidak tersedia, teks asli tetap digunakan.

          

          

            
3. Halaman Web / DOM — Tiket, Agoda, Trip

            
    
              
  1. Pilih Halaman Web / DOM lalu pilih Tiket, Agoda, atau Trip.
    2. 
              
  2. Buka halaman review pada browser MyDataset dan tekan Gunakan Halaman Aktif.
    3. 
              
  3. Pilih field review. MyDataset akan mencari batas satu record dan memvalidasi selector secara semantik.
    4. 
              
  4. Untuk banyak halaman, pilih tombol berikutnya/load more/scroll dan tentukan batas langkah atau Semua yang tersedia.
    5. 
              
  5. Periksa preview sebelum run. Jika website mengubah state halaman atau membatasi browser tertanam, hasil yang sudah aman dipertahankan dan run dapat dihentikan sebagai parsial.
    6. 
            

            
DOM bergantung pada struktur halaman dan sesi browser. Untuk pengambilan data skala besar, gunakan HAR / Network bila tersedia.

          

          

            
4. Memahami hasil

            

              
Hasil CleaningRecord setelah pemeriksaan identitas.

              
Data AsliRecord sebagaimana diperoleh dari sumber.

              
Audit DuplikatDuplikat Pasti dan Potensi Duplikat.

            

            
Setiap run menyimpan metadata website, metode akuisisi, Source URL, waktu, dan status penyelesaian. Run antarwebsite tidak digabung otomatis.

          

          

            
5. Ekspor

            
    
              
  • Data Siap Analisis: skema standar untuk analisis.
    • 
              
  • Data Asli: record sebelum cleaning.
    • 
              
  • Audit Duplikat: record yang perlu diperiksa.
    • 
              
  • Paket Lengkap: dataset, log, metadata run, dan sumber network bila tersedia.
    • 
            

          

          

            
6. Kualitas dan provenance

            
    
              
  • Nilai yang tidak tersedia dari sumber dibiarkan kosong, bukan ditebak.
    • 
              
  • HAR mempertahankan Source URL, response count, review count, endpoint, pagination, serta metadata coverage yang tersedia dari masing-masing sumber.
    • 
              
  • DOM mempertahankan URL halaman, struktur record, selector field, pagination, dan checkpoint run yang benar-benar digunakan.
    • 
              
  • Traveloka, Tiket, Agoda, Trip, dan Booking memakai adapter Network terpisah; DOM memiliki pipeline selector tersendiri untuk Tiket, Agoda, dan Trip.
    • 
              
  • Gunakan Alur Proses untuk mengikuti tahap aktif dan Rincian Proses bila membutuhkan log teknis.
    • 
            

          

          

            
7. Jika terjadi kegagalan

            
Jika pengambilan data berhenti, MyDataset menampilkan dialog yang menjelaskan tahap, kode kegagalan, kemungkinan penyebab, dan jumlah data yang sudah aman.

            
    
              
  • Coba Lagi: melanjutkan dari checkpoint terakhir jika tersedia, bukan menghapus data yang sudah berhasil.
    • 
              
  • Hentikan Proses: menyimpan run sebagai hasil parsial/terhenti dan mempertahankan data yang sudah terkumpul.
    • 
              
  • Pada Alur Proses, node hijau berarti sedang aktif dan node merah berarti gagal.
    • 
            

          

        

      

      

    

  

  
    

      

        
CARA KERJA SISTEM
Bagaimana MyDataset mengolah review
Ringkasan proses HAR / Network dan Halaman Web / DOM.

        
      

      

        

          
          
          
          
          
        

        

          

            
1. Gambaran

            
Setiap pengambilan data mengikuti pola yang sama: sumber dibaca, record diekstrak, data divalidasi, duplikat diperiksa, lalu hasil disimpan.

            
Alur utamaSumber → Ekstraksi → Validasi → Normalisasi → Pemeriksaan Duplikat → Dataset.

          

          

            
2. HAR / Network

            
MyDataset membaca HAR Chrome, mengenali Traveloka, Tiket, Agoda, Trip, atau Booking, memeriksa endpoint review dan pagination, lalu membentuk record sumber tanpa bergantung pada DOM halaman.

          

          

            
3. Halaman Web / DOM

            
MyDataset membaca halaman aktif melalui browser internal, memvalidasi batas record dan field yang dipilih, mengikuti pagination bila diperlukan, lalu masuk ke pipeline normalisasi dan audit yang sama. DOM tersedia untuk Tiket, Agoda, dan Trip.

          

          

            
4. Pemeriksaan duplikat

            

              
Duplikat PastiIdentitas sumber sama. Record duplikat dapat dikeluarkan.

              
Potensi DuplikatID berbeda tetapi mempunyai kemiripan kuat. Record tetap dipertahankan untuk audit.

            

          

          

            
5. Alur & Rincian Proses

            
Alur Proses menunjukkan tahap yang sedang aktif. Rincian Proses menampilkan log teknis jika pengguna perlu memeriksa kegagalan atau audit run.
